WebI Change Source — Quick Start

Bulk-change the data source of Web Intelligence documents using PowerShell and the BI REST API. No extra software needed on Windows.

What this does

This tool opens one or more Web Intelligence documents via the BI REST API, finds their data providers (queries), and changes the universe/data source to a target data source of your choice. It can process many document IDs in a single run.

It does not create the target data source. The target data source must already exist and be accessible in your SAP BusinessObjects environment before you run this tool.

How to find SI_IDs

Target data source — In the CMC, go to Universes, right-click the universe → Properties → General. The SI_ID is shown there (e.g. 5406).
Or query the REST API: 

GET http://myserver:8080/biprws/infostore?query=SELECT SI_ID,SI_NAME FROM CI_INFOOBJECTS WHERE SI_NAME='My Universe'

WebI documents — In the CMC or BI Launchpad, open the document → Properties → General → SI_ID.
Or list all documents: 

GET http://myserver:8080/raylight/v1/documents

Returns a JSON list with id (= SI_ID), name, and folderId for each document.

Step-by-step

1

Clone the repository

git clone https://github.com/SAP-samples/businessobjects-suite-howto-and-samples
cd businessobjects-suite-howto-and-samples\web-intelligence\bi-2027\Automation-BI-Framework\ChangeSource
2

Create your local config

Copy-Item .\bruno\environments\my-env.bru.template .\Powershell\environments\my-env.bru

Open Powershell\environments\my-env.bru in any text editor and fill in your values:

vars {
  baseUrl: http://myserver:8080     # Tomcat root — do NOT include /biprws
  cms: myserver:6400
  user: alice
  password: mysecretpassword
  auth: secEnterprise               # secEnterprise | secLDAP | secWinAD | secSAPR3
  targetuniverse: 5406              # SI_ID of the target data source
  runnerAction: test                # keep "test" until you have reviewed the dry run
  strategyMode: default
  docIds: 5418,5403,62362           # comma-separated WebI document SI_IDs
  logonToken:           # leave blank — filled at runtime by the script
  mappingPayload:        # leave blank — filled at runtime by the script
  mappingStrategies:     # leave blank to use the safe default (see Mapping strategies section)
}
Where does each launcher look? The .bat files resolve environments\my-env.bru relative to their own folder: Powershell\ reads Powershell\environments\my-env.bru; java\ reads java\environments\my-env.bru. The template at bruno\environments\my-env.bru.template is the source to copy from — create one copy per runner you use.
Set runnerAction: test first. Only switch to change after reviewing the dry-run output.
3

Dry run — verify the mapping

cd .\Powershell
.\Run-ChangeSource-PowerShell.bat -Test

The .bat automatically resolves the path to bruno\environments\my-env.bru relative to its own location — you don’t need to cd back to the repo root.

The script logs in, opens each document, computes the source-to-target mapping, prints the result, and logs off. No document is saved or changed. Documents with multiple queries (data providers) are fully supported — each query is processed individually.

Override docIds for a single run without editing the config:

.\Run-ChangeSource-PowerShell.bat -DocIds "5418,5403" -Test
What to look for: for each query you should see [MAP:...] X object mapping(s), 0 not-Ok. Any not-Ok count above zero means some report objects could not be matched to the target — check the target SI_ID and consider using strategyMode: custom.
4

Apply the change

Once the dry-run output looks correct, run in change mode:

.\Run-ChangeSource-PowerShell.bat

The script applies the mapping and saves each document. Lines tagged [CHANGE] confirm each data provider was updated.

Save is automatic and immediate. As soon as a data provider is successfully changed, the document is saved with no further confirmation. If no data provider was changed (e.g. all mappings failed), the document is not saved. Keep a backup according to your team’s operational practice before running this step.

Mapping strategies

The strategyMode config value controls how report objects in the source data provider are matched to objects in the target data source.

strategyModeBehaviour
defaultServer’s built-in matching — plain GET, no strategies body sent.
customYou control the matching rules via the mappingStrategies JSON variable.

When strategyMode: custom and mappingStrategies is blank, the following safe default is used automatically:

{
  "strategies": {
    "strategy": [
      { "name": "SamePath",          "enabled": true  },
      { "name": "SameTechnicalName", "enabled": true  },
      { "name": "SameName",          "enabled": true  },
      { "name": "Removal",           "enabled": false }
    ]
  }
}
StrategyWhat it does
SamePathMatch objects by folder path in the data source.
SameTechnicalNameMatch by technical name.
SameNameMatch by display name.
Removalfalse (recommended) — unmatched report objects are kept. Set to true to remove them.

To override, paste your JSON directly into the mappingStrategies line in my-env.bru:

mappingStrategies: {"strategies":{"strategy":[{"name":"SamePath","enabled":true},{"name":"Removal","enabled":false}]}}

Or pass -StrategyMode custom on the command line — the script uses the value from mappingStrategies in the config, or falls back to the safe default if it is blank.

Strategies apply to the compute step only. They must be sent on the mapping GET request. Sending strategies on the POST (apply) request is rejected by the server with 400 WSR 00103.

Troubleshooting

SymptomFix
Env file not foundConfirm Powershell\environments\my-env.bru exists (copy from bruno\environments\my-env.bru.template). Each launcher reads the env file from its own folder.
Logon failed (401)Check baseUrl (no trailing /biprws), cms, user, password, auth.
Document not found (404)Verify the document SI_ID in docIds in the CMC.
Not authorized (403)The user must have rights to open the document and use the target universe.
Wrong universe in mappingStop before change mode. Verify targetuniverse SI_ID in the CMC.
No documents processedCheck that docIds is set in the config or passed with -DocIds.

Alternative runners

PowerShell is the simplest option on Windows. The same my-env.bru config file is read by all runners.

Bruno — interactive, step-by-step exploration

Useful when you want to inspect each HTTP request and response individually.

  1. Install the Bruno desktop app (free, v1.x or later).
  2. Open the bruno/ folder as a collection.
  3. Select the my-env environment.
  4. Run 00 - Bulk Change Source (All-in-One) for a full run, or use requests 01–07 individually for debugging.
Java — no JAR required

Requires a JDK (not just a JRE) with javac on PATH. The launcher compiles java\ChangeSource.java automatically.

cd ChangeSource\java
Run-ChangeSource-JavaNoJar.bat --test                         # dry run
Run-ChangeSource-JavaNoJar.bat                                # apply
Run-ChangeSource-JavaNoJar.bat --docIds 5418,5403 --test      # override docIds

If javac is missing: install a JDK (e.g. Eclipse Temurin 17 or 21), set JAVA_HOME to the JDK folder, add %JAVA_HOME%\bin to PATH, then open a new terminal.

Keep environments\my-env.bru out of source control — it contains credentials. The template (my-env.bru.template) is tracked by git and safe to commit.
